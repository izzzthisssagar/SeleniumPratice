Why Exception Handling is Critical in Selenium

⏰ Hour 1 — Exception Fundamentals (60 mins)

Selenium tests interact with live browsers, real networks, and dynamic web pages. Things go wrong constantly — elements don't load in time, pages redirect unexpectedly, networks stall. Without exception handling, one failure crashes the entire test run. With it, you control the failure, log it, take a screenshot, and continue.

SituationException ThrownYour Handler Does
Element not found on pageNoSuchElementExceptionLog error + take screenshot + fail test gracefully
Element found but page refreshedStaleElementReferenceExceptionRe-find element and retry
Wait ran out before element appearedTimeoutExceptionLog timeout + report which element was missing
Element exists but not clickable yetElementNotInteractableExceptionScroll to element or wait longer
Browser driver crashedWebDriverExceptionRestart driver + retry test
driver.quit() must always runAny exceptionfinally block ensures browser always closes

What is an Exception?

An exception is an event that disrupts normal program execution. When Java encounters an error at runtime, it creates an exception object and "throws" it. If nothing catches it, the program crashes with a stack trace.

Exception Hierarchy — Checked vs Unchecked

// Java Exception Hierarchy
TypeDescriptionMust Handle?Examples
ErrorJVM-level fatal problem. Never catch these.No (don't touch)OutOfMemoryError, StackOverflowError
Checked ExceptionCompiler forces you to handle or declare. Represents recoverable situations.YES — compile error if not handledIOException, SQLException, FileNotFoundException
Unchecked Exception (RuntimeException)Programmer errors. Compiler doesn't force handling.No (but you should)NullPointerException, ArrayIndexOutOfBoundsException, all Selenium exceptions
📌
All Selenium exceptions are RuntimeExceptions (Unchecked)

This means the compiler won't force you to catch them — but you should handle the important ones. NoSuchElementException, TimeoutException, StaleElementReferenceException are all unchecked. They extend WebDriverException which extends RuntimeException.

04

try-catch Block

The try block contains code that might throw an exception. The catch block handles it if it does. If no exception occurs, the catch block is completely skipped.

JavaTryCatch.java
// Without try-catch — program crashes if 0 is passed
public static int divide_BAD(int a, int b) {
    return a / b;  // ArithmeticException if b == 0
}

// With try-catch — handles the error gracefully
public static int divide(int a, int b) {
    try {
        return a / b;                    // line that might throw
    } catch (ArithmeticException e) {   // catch specific exception type
        System.out.println("Error: Cannot divide by zero");
        System.out.println("Message: " + e.getMessage()); // "/ by zero"
        return -1;                         // return safe default
    }
}

// Usage
System.out.println(divide(10, 2));   // 5  — no exception
System.out.println(divide(10, 0));   // Error printed, returns -1

// catch gives you access to the exception object 'e'
// e.getMessage()    → short description
// e.toString()      → class name + message
// e.printStackTrace() → full stack trace (for debugging)
05

Multiple catch Blocks

One try block can have multiple catch blocks — each handling a different exception type. Java checks them top to bottom and runs the first matching one. Always catch specific exceptions before general ones.

JavaMultipleCatch.java
public static void processData(String[] data, int index) {
    try {
        String value   = data[index];          // may throw ArrayIndexOutOfBoundsException
        int    number  = Integer.parseInt(value); // may throw NumberFormatException
        int    result  = 100 / number;          // may throw ArithmeticException
        System.out.println("Result: " + result);
    }
    catch (ArrayIndexOutOfBoundsException e) {
        System.out.println("Index " + index + " out of bounds. Array size: " + data.length);
    }
    catch (NumberFormatException e) {
        System.out.println("Not a valid number: " + e.getMessage());
    }
    catch (ArithmeticException e) {
        System.out.println("Division by zero");
    }
    catch (Exception e) {        // general catch — ALWAYS last!
        System.out.println("Unexpected: " + e.getMessage());
    }
}

// Multi-catch: handle two exceptions the same way (Java 7+)
try {
    // some code
} catch (NumberFormatException | ArithmeticException e) {
    System.out.println("Number error: " + e.getMessage());
}
🚨
Most specific exception FIRST — always

If you put catch (Exception e) first, it catches EVERYTHING — your specific handlers below it never run. Java forces you to put child classes before parent classes in catch chains. Exception is always last. RuntimeException before Exception.

06

finally Block

The finally block ALWAYS runs — whether an exception occurred or not, whether it was caught or not. This is where driver.quit() lives in your Selenium tests — the browser MUST close no matter what happens.

JavaFinally.java
// Structure
try {
    // risky code
} catch (Exception e) {
    // handle error
} finally {
    // ALWAYS runs — cleanup goes here
}

// Selenium pattern — driver.quit() in finally
public static void runLoginTest() {
    String driver = "ChromeDriver";   // simulating WebDriver

    try {
        System.out.println("[SETUP] Browser started: " + driver);
        System.out.println("[TEST]  Navigating to login page");
        System.out.println("[TEST]  Entering credentials");

        // Simulate a test failure
        if (true) throw new RuntimeException("Login button not found!");

        System.out.println("[TEST]  Login successful");  // never reached

    } catch (RuntimeException e) {
        System.out.println("[FAIL]  Test failed: " + e.getMessage());
        System.out.println("[SCRN]  Screenshot saved: login_fail.png");

    } finally {
        // This ALWAYS runs — even if catch block throws another exception
        System.out.println("[QUIT]  driver.quit() — browser closed");
    }
}

// Output (even though test failed):
// [SETUP] Browser started: ChromeDriver
// [TEST]  Navigating to login page
// [TEST]  Entering credentials
// [FAIL]  Test failed: Login button not found!
// [SCRN]  Screenshot saved: login_fail.png
// [QUIT]  driver.quit() — browser closed   ← always!

try-with-resources

Automatically closes resources (files, connections) after the try block — even if an exception occurs. The resource must implement AutoCloseable. Cleaner than writing finally { resource.close(); }.

JavaTryWithResources.java
import java.io.*;

// OLD WAY — manual close in finally
BufferedReader reader = null;
try {
    reader = new BufferedReader(new FileReader("data.txt"));
    String line = reader.readLine();
} catch (IOException e) {
    e.printStackTrace();
} finally {
    if (reader != null) {
        try { reader.close(); } catch (IOException e) { }
    }
}

// NEW WAY — try-with-resources (Java 7+)
// Resource declared in try() — auto-closed when block ends
try (BufferedReader br = new BufferedReader(new FileReader("data.txt"))) {
    String line = br.readLine();
    System.out.println(line);
} catch (IOException e) {
    System.out.println("File error: " + e.getMessage());
}
// br is automatically closed — no finally needed!

throw — Throwing an Exception Manually

You can intentionally throw an exception using throw. Use it to signal that a method received invalid input or that a test precondition failed.

JavaThrowKeyword.java
public static void login(String username, String password) {

    // Validate inputs before doing anything
    if (username == null || username.isEmpty()) {
        throw new IllegalArgumentException("Username cannot be null or empty");
    }
    if (password == null || password.length() < 6) {
        throw new IllegalArgumentException("Password must be at least 6 characters");
    }

    System.out.println("Logged in as: " + username);
}

// Catching manually thrown exceptions
try {
    login("", "pass123");
} catch (IllegalArgumentException e) {
    System.out.println("Validation failed: " + e.getMessage());
}
// Validation failed: Username cannot be null or empty

try {
    login("Admin", "123");
} catch (IllegalArgumentException e) {
    System.out.println("Validation failed: " + e.getMessage());
}
// Validation failed: Password must be at least 6 characters

throws — Declaring Exceptions in Method Signature

throws in a method signature tells callers "this method might throw this exception — you handle it." Required for checked exceptions. Optional for unchecked (but good documentation).

JavaThrowsDeclaration.java
import java.io.*;

// throws in signature = "caller must handle IOException"
public static String readConfig(String path) throws IOException {
    BufferedReader br = new BufferedReader(new FileReader(path));
    return br.readLine();
    // IOException NOT handled here — passed to caller
}

// Caller MUST handle it
public static void main(String[] args) {
    try {
        String url = readConfig("config.properties");
        System.out.println("URL: " + url);
    } catch (IOException e) {
        System.out.println("Config file not found: " + e.getMessage());
    }
}

// throw vs throws — remember the difference:
// throw  → action: actually throws the exception object
// throws → declaration: warns callers this method may throw

Custom Exceptions

Create your own exception classes for domain-specific errors. In Selenium frameworks, custom exceptions make test failure reasons crystal clear — much better than a generic RuntimeException.

JavaCustomException.java
// Custom checked exception
public class TestSetupException extends Exception {
    public TestSetupException(String message) {
        super(message);
    }
    public TestSetupException(String message, Throwable cause) {
        super(message, cause);
    }
}

// Custom unchecked exception
public class ElementNotFoundException extends RuntimeException {
    private String locator;

    public ElementNotFoundException(String locator) {
        super("Element not found using locator: " + locator);
        this.locator = locator;
    }

    public String getLocator() { return locator; }
}

// Using custom exceptions
public static void clickElement(String locatorId) {
    boolean found = false;  // simulate element not found
    if (!found) {
        throw new ElementNotFoundException(locatorId);
    }
}

try {
    clickElement("#loginButton");
} catch (ElementNotFoundException e) {
    System.out.println("FAILED: " + e.getMessage());
    System.out.println("Locator: " + e.getLocator());
}
// FAILED: Element not found using locator: #loginButton
// Locator: #loginButton

Exception Message & Stack Trace

JavaExceptionInfo.java
try {
    int[] arr = {1, 2, 3};
    System.out.println(arr[10]);   // throws ArrayIndexOutOfBoundsException

} catch (ArrayIndexOutOfBoundsException e) {

    // getMessage() — just the error description
    System.out.println("Message: " + e.getMessage());
    // Message: Index 10 out of bounds for length 3

    // getClass().getSimpleName() — exception class name
    System.out.println("Type: " + e.getClass().getSimpleName());
    // Type: ArrayIndexOutOfBoundsException

    // toString() — class name + message
    System.out.println("Full: " + e.toString());
    // Full: java.lang.ArrayIndexOutOfBoundsException: Index 10 ...

    // printStackTrace() — full trace showing which line caused it
    // Use during DEBUG, remove from production code
    e.printStackTrace();
}

Top 8 Selenium Exceptions — Causes & Fixes

Memorize these. You will encounter every single one during Phase 2 and beyond. Knowing them now means you fix them instantly instead of Googling for 30 minutes.

// ── NoSuchElementException ───────────────────────────────────
try {
    // WebElement btn = driver.findElement(By.id("submitBtn"));
    // btn.click();
    System.out.println("Clicking submit...");
    throw new RuntimeException("NoSuchElementException: id=submitBtn");
} catch (RuntimeException e) {
    System.out.println("Element not found: " + e.getMessage());
}

// ── StaleElementReferenceException — retry pattern ───────────
int retries = 0;
boolean success = false;
while (retries < 3 && !success) {
    try {
        // WebElement el = driver.findElement(By.id("item"));
        // el.click();
        System.out.println("Attempt " + (retries+1) + ": clicked element");
        success = true;
    } catch (RuntimeException e) {
        retries++;
        System.out.println("Stale — retrying (" + retries + ")");
    }
}

// ── driver.quit() ALWAYS in finally ──────────────────────────
String driver = "ChromeDriver";
try {
    System.out.println("Running test on " + driver);
    throw new RuntimeException("Test crashed mid-way");
} catch (RuntimeException e) {
    System.out.println("Caught: " + e.getMessage());
} finally {
    System.out.println("driver.quit() called — browser closed ✓");
}

Exception Handling Patterns in Selenium

⏰ Hour 2 — Advanced Patterns (60 mins)
JavaSeleniumPatterns.java — Patterns you will copy into your framework
// PATTERN 1: Safe click — handle non-interactable elements
public static boolean safeClick(String elementId) {
    try {
        System.out.println("Clicking: " + elementId);
        // element.click();
        return true;
    } catch (Exception e) {
        System.out.println("Click failed on [" + elementId + "]: " + e.getMessage());
        return false;
    }
}

// PATTERN 2: Safe getText — return empty string if element gone
public static String safeGetText(String elementId) {
    try {
        // return element.getText();
        return "Welcome, Admin";
    } catch (Exception e) {
        System.out.println("getText failed: " + e.getMessage());
        return "";   // safe empty string instead of crash
    }
}

// PATTERN 3: isElementPresent — no crash if not found
public static boolean isPresent(String elementId) {
    try {
        // driver.findElement(By.id(elementId));
        return true;
    } catch (Exception e) {
        return false;   // element not found = not present
    }
}

// PATTERN 4: BaseTest with guaranteed cleanup
public static void runTest(String testName) {
    String driver = "ChromeDriver";
    try {
        System.out.println("[START] " + testName);
        // ... test steps ...
        System.out.println("[PASS]  " + testName);
    } catch (AssertionError e) {
        System.out.println("[FAIL]  " + testName + ": " + e.getMessage());
        // takeScreenshot(testName + "_fail");
    } catch (Exception e) {
        System.out.println("[ERROR] " + testName + ": " + e.getMessage());
    } finally {
        System.out.println("[QUIT]  driver.quit()");
        // driver.quit();
    }
}

public class Day7Practice {

    // ── Custom exception ─────────────────────────────────────
    static class BrowserNotSupportedException extends RuntimeException {
        public BrowserNotSupportedException(String browser) {
            super("Browser not supported: " + browser);
        }
    }

    // ── Method 1: safe divide ─────────────────────────────────
    public static double safeDivide(int a, int b) {
        try {
            return (double) a / b;
        } catch (ArithmeticException e) {
            System.out.println("  [ERROR] Division by zero — returning 0");
            return 0;
        }
    }

    // ── Method 2: login validator ─────────────────────────────
    public static void validateLogin(String user, String pass) {
        if (user == null || user.isEmpty())
            throw new IllegalArgumentException("Username is required");
        if (pass == null || pass.length() < 6)
            throw new IllegalArgumentException("Password min 6 chars");
        System.out.println("  Credentials valid for: " + user);
    }

    // ── Method 3: browser init ────────────────────────────────
    public static void initBrowser(String browser) {
        switch (browser.toLowerCase()) {
            case "chrome":
            case "firefox":
            case "edge":
                System.out.println("  " + browser + " initialized ✓");
                break;
            default:
                throw new BrowserNotSupportedException(browser);
        }
    }

    // ── Method 4: full test run simulation ───────────────────
    public static void runTest(String name, boolean shouldFail) {
        System.out.println("\n  [START] " + name);
        try {
            if (shouldFail)
                throw new RuntimeException("Element 'submitBtn' not found");
            System.out.println("  [PASS]  " + name);
        } catch (RuntimeException e) {
            System.out.println("  [FAIL]  " + name + ": " + e.getMessage());
        } finally {
            System.out.println("  [QUIT]  Browser closed");
        }
    }

    public static void main(String[] args) {

        System.out.println("====== TASK 1: Safe Division ======");
        System.out.println("10 / 2 = " + safeDivide(10, 2));
        System.out.println("10 / 0 = " + safeDivide(10, 0));
        System.out.println("25 / 4 = " + safeDivide(25, 4));

        System.out.println("\n====== TASK 2: Login Validation ======");
        String[][] logins = {
            {"Admin", "admin123"},
            {"",      "admin123"},
            {"user1", "123"}
        };
        for (String[] l : logins) {
            try {
                validateLogin(l[0], l[1]);
            } catch (IllegalArgumentException e) {
                System.out.println("  [INVALID] " + e.getMessage());
            }
        }

        System.out.println("\n====== TASK 3: Browser Init ======");
        String[] browsers = {"Chrome", "Firefox", "Safari", "Edge"};
        for (String b : browsers) {
            try {
                initBrowser(b);
            } catch (BrowserNotSupportedException e) {
                System.out.println("  [ERROR] " + e.getMessage());
            }
        }

        System.out.println("\n====== TASK 4: Test Run Simulation ======");
        runTest("Login Test",  false);
        runTest("Logout Test", true);
        runTest("Search Test", false);
    }

Common Mistakes

❌ Empty catch block

catch (Exception e) { } — silently swallows errors. You'll never know why your test failed. Always at minimum: System.out.println(e.getMessage()) or e.printStackTrace().

❌ Catching Exception too broadly

Catching Exception for everything means you accidentally catch NPE, ArrayIndex, and other programmer errors. Catch specific exceptions. Only use general catch as a last resort safety net.

❌ Not using finally for cleanup

If driver.quit() is only in the try block, a test failure means browser stays open forever. Always put cleanup in finally.

❌ Catching Error

Never catch OutOfMemoryError or StackOverflowError. These are JVM-level failures — you can't recover. Let them propagate.

❌ throw vs throws confusion

throw new Exception() — actually throws it. throws Exception in method signature — warns callers. Different keywords, different purposes.

❌ Exception order in multi-catch

Putting parent class (Exception) before child class (NullPointerException) — child case never reached. Always most specific first, most general last.

❌ Ignoring checked exceptions

Using throws Exception on every method to avoid handling — bad practice. Handle at the right level. Don't bubble everything to main().

❌ Re-throwing without cause

throw new RuntimeException(e.getMessage()) loses the original stack trace. Use throw new RuntimeException("msg", e) to preserve the cause chain.
