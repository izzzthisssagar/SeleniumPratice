WebDriver Interface — Deep Dive

⏰ Hour 1 — WebDriver Architecture (60 mins)

On Day 5 you learned that WebDriver is an interface. Now let's see exactly what that means in the context of Selenium — every method you call on driver is defined in this interface.

// WebDriver Interface Hierarchy

Because all drivers share the WebDriver interface, you declare your variable as WebDriver driver (the interface type) and assign any concrete driver. Swap Chrome to Firefox by changing one word — the rest of your test code stays identical.

JavaInterfaceType.java
// Interface type on left — concrete class on right
WebDriver driver = new ChromeDriver();   // ← change this one word
// WebDriver driver = new FirefoxDriver(); ← to this
// WebDriver driver = new EdgeDriver();    ← or this

// ALL test code below works unchanged for any browser:
driver.get("https://orangehrm.com");
driver.getTitle();
driver.findElement(By.id("username"));   // Day 14
driver.quit();

// Never do this — you lose portability:
ChromeDriver driver = new ChromeDriver(); // ← BAD — tied to Chrome

DriverFactory — Reusable Driver Creation

Instead of repeating WebDriverManager.chromedriver().setup(); new ChromeDriver(); in every test, build a DriverFactory class once. This is the first piece of your final framework architecture — it will be used from Day 10 through Day 65.

JavaDriverFactory.java — utils/DriverFactory.java
package com.qaautomation.utils;

import io.github.bonigarcia.wdm.WebDriverManager;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;
import org.openqa.selenium.chrome.ChromeOptions;
import org.openqa.selenium.firefox.FirefoxDriver;
import org.openqa.selenium.firefox.FirefoxOptions;
import org.openqa.selenium.edge.EdgeDriver;
import java.time.Duration;

public class DriverFactory {

    // Config constants
    private static final int    IMPLICIT_WAIT   = 10;
    private static final int    PAGE_LOAD_WAIT  = 30;
    private static final String DEFAULT_BROWSER = "chrome";

    // Create driver by browser name — reads from system property or uses default
    public static WebDriver getDriver() {
        String browser = System.getProperty("browser", DEFAULT_BROWSER);
        return getDriver(browser);
    }

    public static WebDriver getDriver(String browser) {
        WebDriver driver;

        switch (browser.toLowerCase().trim()) {

            case "chrome":
                WebDriverManager.chromedriver().setup();
                ChromeOptions chromeOpts = new ChromeOptions();
                chromeOpts.addArguments("--disable-notifications");
                chromeOpts.addArguments("--disable-infobars");
                driver = new ChromeDriver(chromeOpts);
                break;

            case "chrome-headless":
                WebDriverManager.chromedriver().setup();
                ChromeOptions headlessOpts = new ChromeOptions();
                headlessOpts.addArguments("--headless=new");
                headlessOpts.addArguments("--window-size=1920,1080");
                headlessOpts.addArguments("--disable-notifications");
                driver = new ChromeDriver(headlessOpts);
                break;

            case "firefox":
                WebDriverManager.firefoxdriver().setup();
                driver = new FirefoxDriver();
                break;

            case "edge":
                WebDriverManager.edgedriver().setup();
                driver = new EdgeDriver();
                break;

            default:
                throw new IllegalArgumentException(
                    "Browser not supported: " + browser
                    + ". Use: chrome, chrome-headless, firefox, edge"
                );
        }

        // Apply common settings to all browsers
        driver.manage().window().maximize();
        driver.manage().deleteAllCookies();
        driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(IMPLICIT_WAIT));
        driver.manage().timeouts().pageLoadTimeout(Duration.ofSeconds(PAGE_LOAD_WAIT));

        return driver;
    }
}

// Usage in any test class — just one line:
WebDriver driver = DriverFactory.getDriver("chrome");
// or with system property: mvn test -Dbrowser=firefox
WebDriver driver2 = DriverFactory.getDriver(); // reads -Dbrowser param
🌟
This is real framework code

The DriverFactory you just wrote is production-grade. Every professional Selenium framework has exactly this pattern. When you reach Phase 4 CI/CD, you'll pass -Dbrowser=chrome-headless to GitHub Actions and this factory handles the rest automatically.

Timeouts — Implicit, Page Load, Script

Selenium has 3 types of timeouts. Understanding the difference is critical — wrong timeout settings cause either slow tests (too long) or flaky tests (too short).

Timeout TypeWhat It ControlsWhen to UseTypical Value
implicitlyWaitHow long WebDriver waits for an element before throwing NoSuchElementExceptionSet once globally. Basic safety net.10 seconds
pageLoadTimeoutHow long to wait for a page to fully load after get() or navigate()Always set. Default is too short for slow pages.30 seconds
setScriptTimeoutHow long async JavaScript executes before timeout (Day 25)Only if you use executeAsyncScript()30 seconds
JavaTimeouts.java
import java.time.Duration;

WebDriver driver = DriverFactory.getDriver("chrome");

// ── Implicit Wait ─────────────────────────────────────────────
// Tells WebDriver: when findElement() doesn't find the element,
// wait up to X seconds polling the DOM before throwing exception
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));

// ── Page Load Timeout ─────────────────────────────────────────
// If page takes longer than 30s to load — TimeoutException thrown
driver.manage().timeouts().pageLoadTimeout(Duration.ofSeconds(30));

// ── Script Timeout ────────────────────────────────────────────
// For async JS execution via executeAsyncScript()
driver.manage().timeouts().scriptTimeout(Duration.ofSeconds(30));

// IMPORTANT: Implicit wait vs Explicit wait (Day 20)
// Implicit: set once, applies to all findElement() calls globally
// Explicit: set per-element with WebDriverWait — more precise
// NEVER mix both in the same script — causes unpredictable behavior
// Best practice: use ONLY explicit waits in production frameworks
// For now (Days 9-19): use implicit wait. Switch to explicit on Day 20.

Taking Screenshots

Screenshots are essential for debugging test failures. You capture the browser state at the moment of failure and save it as a PNG file for review.

JavaScreenshots.java
import org.openqa.selenium.TakesScreenshot;
import org.openqa.selenium.OutputType;
import org.apache.commons.io.FileUtils;
import java.io.File;
import java.io.IOException;

// Method 1: Save screenshot to file
public static void takeScreenshot(WebDriver driver, String fileName) {
    try {
        // Cast driver to TakesScreenshot interface
        TakesScreenshot ts = (TakesScreenshot) driver;

        // Capture screenshot as a File
        File screenshot = ts.getScreenshotAs(OutputType.FILE);

        // Copy to your output folder
        File dest = new File("screenshots/" + fileName + ".png");
        FileUtils.copyFile(screenshot, dest);
        System.out.println("Screenshot saved: " + dest.getAbsolutePath());

    } catch (IOException e) {
        System.out.println("Screenshot failed: " + e.getMessage());
    }
}

// Method 2: Get screenshot as Base64 (for embedding in HTML reports)
String base64 = ((TakesScreenshot) driver).getScreenshotAs(OutputType.BASE64);
System.out.println("Base64 length: " + base64.length());

// Usage in test — always screenshot on failure:
try {
    driver.get("https://site.com");
    // ... test steps ...
} catch (Exception e) {
    takeScreenshot(driver, "login_test_FAIL");  // capture state on failure
    throw e;  // re-throw so test still fails properly
} finally {
    driver.quit();
}

// Add commons-io dependency to pom.xml for FileUtils:
//   <dependency>
//     <groupId>commons-io</groupId>
//     <artifactId>commons-io</artifactId>
//     <version>2.15.1</version>
//   </dependency>

BaseTest Class — Framework Foundation

Every professional framework has a BaseTest class that all test classes extend. It handles driver creation, setup, and teardown in one place. This is the exact pattern your framework will use from Day 37 with TestNG annotations.

⏰ Hour 2 — Framework Pattern (60 mins)
JavaBaseTest.java — tests/BaseTest.java
package com.qaautomation.tests;

import com.qaautomation.utils.DriverFactory;
import org.openqa.selenium.WebDriver;

public class BaseTest {

    // protected = accessible by child test classes
    protected WebDriver driver;
    protected String    browser = "chrome";

    // setUp() — runs before each test
    // In TestNG this becomes: @BeforeMethod (Day 27)
    public void setUp() {
        driver = DriverFactory.getDriver(browser);
        System.out.println("[SETUP] " + browser + " started");
    }

    // tearDown() — runs after each test, even on failure
    // In TestNG this becomes: @AfterMethod (Day 27)
    public void tearDown() {
        if (driver != null) {
            driver.quit();
            System.out.println("[QUIT] Browser closed");
        }
    }

    // Helper: take screenshot from any test
    protected void screenshot(String name) {
        System.out.println("[SCRN] Saved: " + name + ".png");
        // Real implementation: ScreenshotUtils.take(driver, name);
    }

    // Helper: navigate and return title
    protected String navigateTo(String url) {
        driver.get(url);
        return driver.getTitle();
    }
}

// ── A test class that extends BaseTest ──────────────────────────
public class LoginPageTest extends BaseTest {

    public void testLoginPageLoads() {
        setUp();  // @BeforeMethod on Day 27 — will call automatically
        try {
            String title = navigateTo("https://opensource-demo.orangehrmlive.com");
            System.out.println("Title: " + title);

            boolean passed = title.equals("OrangeHRM");
            System.out.println(passed ? "✓ PASS" : "✗ FAIL");

        } catch (Exception e) {
            screenshot("login_page_fail");
            System.out.println("Error: " + e.getMessage());
        } finally {
            tearDown();  // @AfterMethod on Day 27 — will call automatically
        }
    }
}

Running Multiple Browsers in Sequence

JavaCrossBrowserRun.java
public class CrossBrowserRun {

    public static void runTest(String browser) {
        WebDriver driver = DriverFactory.getDriver(browser);
        try {
            driver.get("https://opensource-demo.orangehrmlive.com");
            String title   = driver.getTitle();
            String url     = driver.getCurrentUrl();
            boolean passed = title.equals("OrangeHRM");

            System.out.printf("  [%-8s] Title: %-15s URL check: %s  %s%n",
                browser.toUpperCase(), title,
                url.contains("login") ? "PASS" : "FAIL",
                passed ? "✓" : "✗");

        } catch (Exception e) {
            System.out.printf("  [%-8s] ERROR: %s%n", browser, e.getMessage());
        } finally {
            driver.quit();
        }
    }

    public static void main(String[] args) {
        System.out.println("====== CROSS-BROWSER TEST ======");
        String[] browsers = {"chrome", "firefox", "edge"};
        for (String b : browsers) {
            runTest(b);
        }
        System.out.println("====== DONE ======");
    }
}

Common Mistakes

❌ Using ChromeDriver type instead of WebDriver

Declaring ChromeDriver driver = new ChromeDriver() breaks cross-browser flexibility. Always declare as WebDriver driver.

❌ Implicit + Explicit wait together

Mixing implicitlyWait(10) and WebDriverWait in the same script causes unpredictable timing. Choose one. Use explicit wait for Day 20+ framework.

❌ Not null-checking driver in tearDown

If driver creation failed (bad browser name, crash), driver.quit() in finally throws NullPointerException. Always: if (driver != null) driver.quit();

❌ Cookie operations before get()

Selenium throws WebDriverException if you try to manage cookies before loading a URL. Always driver.get(url) first, then handle cookies.

❌ Screenshot folder doesn't exist

If the "screenshots/" directory doesn't exist, FileUtils.copyFile() throws IOException. Create the folder first: new File("screenshots").mkdirs();

❌ Calling setup() from a static context

If your test class methods are static, they can't access instance fields like driver. Either make driver static or use instance methods.
