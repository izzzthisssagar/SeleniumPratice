Why Collections Matter More Than Arrays in Selenium

⏰ Hour 1 — List (60 mins)

Arrays have one fatal flaw for automation: fixed size. You don't know upfront how many elements a page will have. Selenium's findElements() returns a List<WebElement> — you need to know how to work with that from Day 14.

CollectionSelenium Usage
List<WebElement>All elements returned by driver.findElements(By.tagName("a")) — dynamic size
ArrayList<String>Storing all link texts, dropdown options, table cell values for assertion
HashMap<String,String>Test data: username→password pairs, config key→value, expected results map
HashSet<String>Detecting duplicate links or text values on a page (Set removes duplicates)
List<String>Storing browser names for cross-browser test loop

ArrayList — Dynamic Array

ArrayList is like an array that grows and shrinks automatically. It maintains insertion order, allows duplicates, and gives fast access by index. It's backed by a regular array internally but resizes itself when needed.

// Array (fixed) vs ArrayList (dynamic)
JavaArrayList_Basics.java
import java.util.ArrayList;
import java.util.List;

// Declaration — always use List as the type (interface)
List<String> browsers = new ArrayList<>();

// OR declare with initial values
List<String> urls = new ArrayList<>(List.of("https://a.com", "https://b.com"));

// Size at creation
System.out.println(browsers.size()); // 0 — starts empty!
04

ArrayList Core Methods

JavaArrayList_Methods.java
List<String> tests = new ArrayList<>();

// ── ADD ──────────────────────────────────────────────────────
tests.add("Login Test");         // add to end
tests.add("Logout Test");
tests.add("Register Test");
tests.add(0, "Smoke Test");     // add at index 0 (shifts others right)
// ["Smoke Test", "Login Test", "Logout Test", "Register Test"]

// ── ACCESS ───────────────────────────────────────────────────
System.out.println(tests.get(0));          // Smoke Test
System.out.println(tests.get(tests.size()-1)); // Register Test (last)
System.out.println(tests.size());          // 4

// ── SEARCH ───────────────────────────────────────────────────
System.out.println(tests.contains("Login Test")); // true
System.out.println(tests.indexOf("Logout Test")); // 2
System.out.println(tests.isEmpty());              // false

// ── MODIFY ───────────────────────────────────────────────────
tests.set(1, "Login Test — Updated"); // replace at index 1

// ── REMOVE ───────────────────────────────────────────────────
tests.remove("Logout Test");  // by value
tests.remove(0);              // by index — removes "Smoke Test"

// ── CLEAR ALL ────────────────────────────────────────────────
List<String> temp = new ArrayList<>(tests); // copy before clearing
tests.clear();
System.out.println(tests.isEmpty()); // true

// ── SUBLIST ──────────────────────────────────────────────────
List<String> all = new ArrayList<>(List.of("a","b","c","d","e"));
List<String> sub = all.subList(1, 4); // [b, c, d] — from index 1 to 3
System.out.println(sub); // [b, c, d]
⚡
size() not length — List uses size(), arrays use length

Arrays: arr.length (no parentheses). ArrayList: list.size() (with parentheses). Strings: str.length() (with parentheses). Mixing these up is a constant source of confusion — memorize all three right now.

Iterating ArrayList — 4 Ways

JavaArrayList_Iteration.java
List<String> browsers = new ArrayList<>(List.of("Chrome","Firefox","Edge"));

// Way 1: for-each (most common in Selenium)
for (String b : browsers) {
    System.out.println("Testing on: " + b);
}

// Way 2: regular for with index (when you need position)
for (int i = 0; i < browsers.size(); i++) {
    System.out.println(i + ": " + browsers.get(i));
}

// Way 3: Iterator (safe removal during iteration)
import java.util.Iterator;
Iterator<String> it = browsers.iterator();
while (it.hasNext()) {
    String b = it.next();
    if (b.equals("Edge")) {
        it.remove(); // safe removal during loop — never use list.remove() inside for-each!
    }
}

// Way 4: forEach with lambda (Java 8+, clean and modern)
browsers.forEach(b -> System.out.println("Browser: " + b));

// Selenium real usage:
// List<WebElement> links = driver.findElements(By.tagName("a"));
// for (WebElement link : links) {
//     System.out.println(link.getText());  // print each link text
// }

LinkedList — When to Use

LinkedList also implements List but stores elements as nodes linked together. Faster for frequent insertions/deletions at beginning or middle. Slower for random access by index. Use ArrayList for most cases.

OperationArrayListLinkedListUse In Selenium
get(index)Fast O(1)Slow O(n)ArrayList wins — frequent access by index
add to endFastFastEqual
add to front/middleSlow O(n)Fast O(1)LinkedList if building a queue
MemoryLessMore (pointer overhead)ArrayList wins for large element lists
✅
Just use ArrayList 95% of the time

In Selenium automation, you're mostly iterating lists of elements or test data. ArrayList is faster for that use case. Only switch to LinkedList if you have a specific performance reason after profiling.

08

List Interface — Coding to Interface

Always declare your variable as List<T> (the interface) rather than ArrayList<T> (the implementation). This lets you swap implementations without changing code everywhere — exactly how WebDriver works.

JavaListInterface.java
import java.util.*;

// BAD: tied to ArrayList — hard to change later
ArrayList<String> bad = new ArrayList<>();

// GOOD: coded to interface — can swap to LinkedList, etc.
List<String> good = new ArrayList<>();

// Now easily swap without changing code that uses 'good':
List<String> linked = new LinkedList<>();

// Same pattern as Selenium:
// WebDriver driver = new ChromeDriver();   ← interface = WebDriver
// List<WebElement> els = driver.findElements(By.tagName("a")); ← interface = List

⏰ Hour 2 — HashMap & HashSet (60 mins)

A HashMap stores data as key-value pairs. Think of it like a dictionary — you look up a value using its key. Keys are unique, values can repeat. Order is NOT guaranteed.

10

HashMap Core Methods

JavaHashMap_Methods.java
import java.util.HashMap;
import java.util.Map;

// Declaration — always use Map as type (interface)
Map<String, String> credentials = new HashMap<>();

// ── PUT (add / update) ───────────────────────────────────────
credentials.put("username", "Admin");
credentials.put("password", "admin123");
credentials.put("role",     "admin");

// Duplicate key OVERWRITES the value
credentials.put("username", "NewAdmin");  // "Admin" is gone, replaced

// ── GET ──────────────────────────────────────────────────────
System.out.println(credentials.get("username"));    // NewAdmin
System.out.println(credentials.get("nonexistent")); // null (key not found)

// getOrDefault — safe fallback value
String browser = credentials.getOrDefault("browser", "chrome");
System.out.println(browser);  // chrome (key not found, uses default)

// ── SEARCH ───────────────────────────────────────────────────
System.out.println(credentials.containsKey("username"));  // true
System.out.println(credentials.containsValue("admin"));   // true

// ── SIZE & EMPTY ─────────────────────────────────────────────
System.out.println(credentials.size());     // 3
System.out.println(credentials.isEmpty());  // false

// ── REMOVE ───────────────────────────────────────────────────
credentials.remove("role");
System.out.println(credentials.size());  // 2

// ── putIfAbsent — only adds if key doesn't exist ─────────────
credentials.putIfAbsent("username", "WillNotReplace"); // ignored
credentials.putIfAbsent("env", "staging");             // added

Iterating HashMap — 3 Ways

JavaHashMap_Iteration.java
Map<String, String> config = new HashMap<>();
config.put("browser",  "chrome");
config.put("baseUrl",  "https://orangehrm.com");
config.put("timeout",  "30");
config.put("headless", "false");

// Way 1: entrySet — get both key and value (most common)
for (Map.Entry<String, String> entry : config.entrySet()) {
    System.out.println(entry.getKey() + " = " + entry.getValue());
}

// Way 2: keySet — loop keys only
for (String key : config.keySet()) {
    System.out.println("Key: " + key);
}

// Way 3: values — loop values only
for (String val : config.values()) {
    System.out.println("Value: " + val);
}

// Way 4: forEach lambda (Java 8+, cleanest)
config.forEach((k, v) -> System.out.println(k + " → " + v));

HashSet — No Duplicates

A HashSet stores unique values only — duplicates are silently ignored. Order is NOT guaranteed. Use it when you need to detect duplicates or when uniqueness matters.

JavaHashSet.java
import java.util.HashSet;
import java.util.Set;

Set<String> uniqueBrowsers = new HashSet<>();
uniqueBrowsers.add("Chrome");
uniqueBrowsers.add("Firefox");
uniqueBrowsers.add("Chrome");   // duplicate — silently ignored
uniqueBrowsers.add("Edge");
uniqueBrowsers.add("Firefox");  // duplicate — silently ignored

System.out.println(uniqueBrowsers.size());  // 3, not 5
System.out.println(uniqueBrowsers);           // [Chrome, Firefox, Edge] (order varies)

// Check membership
System.out.println(uniqueBrowsers.contains("Chrome"));  // true
System.out.println(uniqueBrowsers.contains("Safari"));  // false

// Selenium use case: detect duplicate links on a page
List<String> allLinks = new ArrayList<>(List.of(
    "https://site.com/home", "https://site.com/about",
    "https://site.com/home", "https://site.com/contact"
));

Set<String> seen       = new HashSet<>();
Set<String> duplicates = new HashSet<>();
for (String link : allLinks) {
    if (!seen.add(link)) {    // add() returns false if already present
        duplicates.add(link);
    }
}
System.out.println("Duplicate links: " + duplicates);
// Duplicate links: [https://site.com/home]

Collections Utility Class

JavaCollectionsUtil.java
import java.util.*;

List<Integer> scores = new ArrayList<>(List.of(78, 95, 62, 88, 71));

// Sort ascending
Collections.sort(scores);
System.out.println(scores);  // [62, 71, 78, 88, 95]

// Sort descending
Collections.sort(scores, Collections.reverseOrder());
System.out.println(scores);  // [95, 88, 78, 71, 62]

// Max and min
System.out.println(Collections.max(scores));  // 95
System.out.println(Collections.min(scores));  // 62

// Shuffle — randomize order
Collections.shuffle(scores);
System.out.println(scores);  // random order

// Frequency — count occurrences
List<String> statuses = new ArrayList<>(List.of("PASS","FAIL","PASS","PASS","FAIL"));
System.out.println(Collections.frequency(statuses, "PASS"));  // 3
System.out.println(Collections.frequency(statuses, "FAIL"));  // 2

// Unmodifiable list — read-only, no add/remove allowed
List<String> readOnly = Collections.unmodifiableList(statuses);
// readOnly.add("PASS"); ← UnsupportedOperationException at runtime

Generics — What <String> Means

The <String> in List<String> is called a generic type parameter. It tells Java what type of objects the collection holds. This gives you compile-time safety — you can't accidentally add an int to a List<String>.

JavaGenerics.java
// Without generics (old way — avoid) — raw type
List rawList = new ArrayList();
rawList.add("Chrome");
rawList.add(42);          // no error! but causes ClassCastException at runtime

// With generics (correct way) — type-safe at compile time
List<String> safeList = new ArrayList<>();
safeList.add("Chrome");
// safeList.add(42);   ← COMPILE ERROR — caught before runtime!

// Common generic types you'll use in Selenium:
List<String>                 stringList  = new ArrayList<>();
List<Integer>                intList     = new ArrayList<>();
Map<String, String>         strMap      = new HashMap<>();
Map<String, Integer>        countMap    = new HashMap<>();
Map<String, List<String>> nestedMap   = new HashMap<>();

// Note: can't use primitives in generics — use wrapper classes!
// List<int>    ← WRONG (int is primitive)
// List<Integer> ← CORRECT (Integer is wrapper class)
// int ↔ Integer auto-boxing/unboxing happens automatically
List<Integer> nums = new ArrayList<>();
nums.add(5);          // auto-boxing: int 5 → Integer 5
int n = nums.get(0);  // auto-unboxing: Integer 5 → int 5

Common Mistakes

❌ .length on ArrayList

list.length doesn't exist. ArrayList uses list.size(). Arrays use arr.length. Strings use str.length(). All three different.

❌ remove(int) vs remove(Object)

list.remove(1) removes by INDEX. list.remove("Chrome") removes by VALUE. Removing an Integer from List<Integer>: use list.remove(Integer.valueOf(5)) not list.remove(5) (would remove index 5).

❌ Modifying list inside for-each

Calling list.remove() inside a for-each loop throws ConcurrentModificationException. Use Iterator.remove() or loop backwards using a regular for loop.

❌ HashMap doesn't guarantee order

HashMap iteration order is not insertion order. If you need insertion order, use LinkedHashMap. If you need sorted order, use TreeMap.

❌ get() returns null for missing key

map.get("nonexistent") returns null. Calling a method on null crashes. Use containsKey() first, or use getOrDefault(key, defaultValue).

❌ Using primitives in generics

List<int> doesn't compile. Use wrapper classes: List<Integer>, List<Double>, List<Boolean>. Auto-boxing handles the int↔Integer conversion.

❌ Iterating HashSet by index

Set has no get(index) method. You can only iterate with for-each or iterator. If you need indexed access, use a List instead.

❌ NullPointerException from unboxing

int x = map.get("key") when key doesn't exist — map returns null, auto-unboxing null throws NullPointerException. Always check with getOrDefault or containsKey first.
