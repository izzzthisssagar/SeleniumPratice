Class vs Object — Blueprint vs Instance

A class is a blueprint — it defines what something looks like and what it can do. An object is the actual thing created from that blueprint. You can create unlimited objects from one class, each with their own data.

// Class = Blueprint     Object = Instance (actual thing)
04

Anatomy of a Class — Every Part Labelled

JavaUserClass.java — complete class anatomy
public class User {               // ← Class declaration (filename must match)

    // ── FIELDS (instance variables) ──────────────────────────
    // Each object gets its own copy of these
    private String  username;          // private = only accessed via methods
    private String  password;
    private String  role;
    private boolean isActive;

    // ── CONSTRUCTOR ───────────────────────────────────────────
    // Same name as class. No return type. Runs when new User() is called.
    public User(String username, String password, String role) {
        this.username = username;       // this.field = parameter
        this.password = password;
        this.role     = role;
        this.isActive = true;          // default value
    }

    // ── GETTERS (read private fields) ─────────────────────────
    public String  getUsername() { return username; }
    public String  getRole()     { return role; }
    public boolean isActive()   { return isActive; }

    // ── SETTERS (modify private fields) ───────────────────────
    public void setRole(String role) { this.role = role; }
    public void setActive(boolean active) { this.isActive = active; }

    // ── BEHAVIOUR METHODS ─────────────────────────────────────
    public void login() {
        if (!isActive) {
            System.out.println(username + " account is disabled");
            return;
        }
        System.out.println(username + " logged in as " + role);
    }

    public void logout() {
        System.out.println(username + " logged out.");
    }

    // ── toString ──────────────────────────────────────────────
    public String toString() {
        return "User[" + username + " | " + role + " | active=" + isActive + "]";
    }

}   // ← closing brace of class
05

Fields (Instance Variables)

Fields are variables declared inside a class but outside any method. Every object gets its own independent copy of all fields — changing one object's fields doesn't affect another object's fields.

JavaFields.java
public class TestResult {
    // Fields — each object gets its own copy
    String  testName;
    boolean passed;
    int     duration;
    String  browser;
}

// In main — two completely independent objects
TestResult t1 = new TestResult();
t1.testName = "Login Test";
t1.passed   = true;
t1.duration = 3;

TestResult t2 = new TestResult();
t2.testName = "Logout Test";
t2.passed   = false;
t2.duration = 1;

// Changing t1 does NOT affect t2
t1.passed = false;
System.out.println(t1.passed);   // false
System.out.println(t2.passed);   // false (unchanged)

Constructors — Creating Objects

A constructor is a special method that runs automatically when you create a new object with new. It initializes the object's fields. Constructor rules: same name as class, no return type (not even void).

// Constructor Execution Flow
JavaConstructors.java
public class User {
    String username;
    String password;
    String role;

    // Constructor — same name as class, NO return type
    public User(String username, String password, String role) {
        this.username = username;
        this.password = password;
        this.role     = role;
    }

    public void printInfo() {
        System.out.println("User: " + username + " | Role: " + role);
    }
}

// Creating objects
User admin = new User("Admin", "admin123", "admin");
User tester = new User("sagar", "test@99", "user");

admin.printInfo();   // User: Admin | Role: admin
tester.printInfo();  // User: sagar | Role: user
07

The this Keyword

this refers to the current object. It's used when a parameter name is the same as a field name — this.fieldName means "the field of this object", not the local parameter.

JavaThisKeyword.java
public class Browser {
    String name;      // ← field
    int    version;   // ← field

    // Without this — PROBLEM: parameter shadows field
    public Browser_BAD(String name, int version) {
        name    = name;     // ← assigns parameter to itself! field unchanged!
        version = version;  // ← same bug!
    }

    // With this — CORRECT: field gets the value
    public Browser(String name, int version) {
        this.name    = name;    // ← this.name = field, name = parameter
        this.version = version; // ← correct assignment
    }

    // this used in method to refer to current object's field
    public void print() {
        System.out.println(this.name + " v" + this.version);
    }
}

Browser chrome = new Browser("Chrome", 120);
chrome.print();  // Chrome v120
⚡
Always use this. in constructors — no exceptions

When your parameter names match your field names (which they should for readability), you MUST use this. to distinguish them. Forgetting it is a silent bug — Java won't warn you, but your fields will all be null or zero.

08

Constructor Overloading

Multiple constructors for the same class — each with different parameters. Java picks the right one based on arguments. Common in Selenium page objects (some need driver, some need driver + url).

JavaConstructorOverload.java
public class TestConfig {
    String  browser;
    String  baseUrl;
    int     timeout;
    boolean headless;

    // Constructor 1: minimal config
    public TestConfig(String browser) {
        this.browser  = browser;
        this.baseUrl  = "https://opensource-demo.orangehrmlive.com";
        this.timeout  = 30;
        this.headless = false;
    }

    // Constructor 2: full config
    public TestConfig(String browser, String url, int timeout, boolean headless) {
        this.browser  = browser;
        this.baseUrl  = url;
        this.timeout  = timeout;
        this.headless = headless;
    }

    public void print() {
        System.out.println("Browser: " + browser + " | Timeout: " + timeout
                           + "s | Headless: " + headless);
    }
}

TestConfig c1 = new TestConfig("chrome");  // uses constructor 1
TestConfig c2 = new TestConfig("firefox", "https://site.com", 60, true);
c1.print(); // Browser: chrome | Timeout: 30s | Headless: false
c2.print(); // Browser: firefox | Timeout: 60s | Headless: true
09

Instance Methods Inside a Class

JavaInstanceMethods.java
public class BankAccount {
    private String owner;
    private double balance;

    public BankAccount(String owner, double initial) {
        this.owner   = owner;
        this.balance = initial;
    }

    // void method — performs action on this object's state
    public void deposit(double amount) {
        if (amount <= 0) {
            System.out.println("Invalid deposit");
            return;
        }
        balance += amount;
        System.out.println("Deposited: " + amount + ". New balance: " + balance);
    }

    public void withdraw(double amount) {
        if (amount > balance) {
            System.out.println("Insufficient funds");
            return;
        }
        balance -= amount;
        System.out.println("Withdrew: " + amount + ". Balance: " + balance);
    }

    // return method — reads this object's state
    public double getBalance() { return balance; }
}

BankAccount acc = new BankAccount("Sagar", 1000.0);
acc.deposit(500);    // Deposited: 500.0. New balance: 1500.0
acc.withdraw(200);   // Withdrew: 200.0. Balance: 1300.0
acc.withdraw(9999);  // Insufficient funds
System.out.println(acc.getBalance());  // 1300.0

Getters & Setters (Encapsulation)

Make fields private so nothing outside the class can directly touch them. Provide public getter/setter methods for controlled access. This is encapsulation — the most important OOP pillar for QA automation.

JavaEncapsulation.java
public class TestUser {

    // private = cannot be accessed directly from outside this class
    private String username;
    private int    age;

    public TestUser(String username, int age) {
        this.username = username;
        this.age      = age;
    }

    // GETTER: returns value — read-only access
    public String getUsername() { return username; }
    public int    getAge()      { return age; }

    // SETTER: with validation — controlled write access
    public void setAge(int age) {
        if (age < 0 || age > 120) {
            System.out.println("Invalid age: " + age);
            return;
        }
        this.age = age;
    }
}

TestUser u = new TestUser("sagar", 22);

// u.age = -5;  ← ERROR: age is private — cannot touch directly
u.setAge(-5);                        // prints: Invalid age: -5 (protected)
u.setAge(23);                        // valid — updates age
System.out.println(u.getUsername()); // sagar
System.out.println(u.getAge());      // 23
📌
Selenium POM uses this pattern exactly

In your Page Object class, WebElements are private (the test can't grab them directly). Page methods are public (the test calls page.clickLogin()). The test never knows or cares HOW the click happens — it just calls the method. That is encapsulation in action.

Creating & Using Multiple Objects

JavaMultipleObjects.java
public class TestCase {
    String  name;
    boolean passed;
    int     priority;  // 1=high, 2=medium, 3=low

    public TestCase(String name, boolean passed, int priority) {
        this.name     = name;
        this.passed   = passed;
        this.priority = priority;
    }

    public void print() {
        String status = passed ? "PASS" : "FAIL";
        String pLevel = priority == 1 ? "HIGH" : priority == 2 ? "MED" : "LOW";
        System.out.printf("[%s] %-25s P:%s%n", status, name, pLevel);
    }
}

// Create an array of objects
TestCase[] suite = {
    new TestCase("Login - valid creds",    true,  1),
    new TestCase("Login - wrong password",  false, 1),
    new TestCase("Search employee",         true,  2),
    new TestCase("Export PDF report",       false, 3),
};

// Loop through array of objects
int passed = 0;
for (TestCase tc : suite) {
    tc.print();
    if (tc.passed) passed++;
}
System.out.println("\nTotal: " + passed + "/" + suite.length + " passed");
// [PASS] Login - valid creds        P:HIGH
// [FAIL] Login - wrong password     P:HIGH
// [PASS] Search employee            P:MED
// [FAIL] Export PDF report          P:LOW
// Total: 2/4 passed

Static Fields & Methods vs Instance

JavaStaticVsInstance.java
public class Counter {

    // STATIC field — ONE copy shared by ALL objects
    static int totalCreated = 0;

    // INSTANCE field — EACH object has its own copy
    String name;
    int    count;

    public Counter(String name) {
        this.name  = name;
        this.count = 0;
        totalCreated++;   // increment shared counter every time
    }

    public void increment() { count++; }

    // STATIC method — no object needed to call
    public static int getTotal() { return totalCreated; }
}

Counter c1 = new Counter("loginCount");
Counter c2 = new Counter("clickCount");
Counter c3 = new Counter("errorCount");

c1.increment(); c1.increment(); // c1.count = 2
c2.increment();               // c2.count = 1

System.out.println(c1.count);           // 2  (own count)
System.out.println(c2.count);           // 1  (own count)
System.out.println(Counter.getTotal()); // 3  (shared — 3 objects created)
13

toString() Method

Override toString() so when you print an object directly, you get a readable description instead of a memory address like User@7d4991ad.

JavaToString.java
public class TestRun {
    String  env;
    String  browser;
    boolean passed;

    public TestRun(String env, String browser, boolean passed) {
        this.env     = env;
        this.browser = browser;
        this.passed  = passed;
    }

    // Override toString — called automatically when you println an object
    public String toString() {
        return String.format("TestRun[env=%s, browser=%s, passed=%s]",
                              env, browser, passed);
    }
}

TestRun run = new TestRun("staging", "Chrome", true);

System.out.println(run);
// WITHOUT toString override: TestRun@7d4991ad  ← useless
// WITH    toString override: TestRun[env=staging, browser=Chrome, passed=true]
14

Objects as Parameters

JavaObjectParams.java
public class Report {

    // Method accepts a TestCase object as parameter
    public static void printResult(TestCase tc) {
        String s = tc.passed ? "PASS" : "FAIL";
        System.out.println("[" + s + "] " + tc.name);
    }

    // Method accepts array of objects
    public static int countFailed(TestCase[] tests) {
        int count = 0;
        for (TestCase t : tests) if (!t.passed) count++;
        return count;
    }

    public static void main(String[] args) {
        TestCase t1 = new TestCase("Login",  true,  1);
        TestCase t2 = new TestCase("Logout", false, 2);

        printResult(t1);  // [PASS] Login
        printResult(t2);  // [FAIL] Logout

        TestCase[] all = {t1, t2};
        System.out.println("Failed: " + countFailed(all));  // 1
    }
}

Practice Task + Expected Output

Type all of this from scratch. This is the most realistic QA-focused OOP task so far — a mini test management system using proper classes and objects.

JavaDay4Practice.java
public class Day4Practice {

    // ── Inner Class: TestCase ────────────────────────────────
    static class TestCase {
        private String  name;
        private boolean passed;
        private int     durationSec;
        private String  browser;

        public TestCase(String name, boolean passed, int dur, String browser) {
            this.name        = name;
            this.passed      = passed;
            this.durationSec = dur;
            this.browser     = browser;
        }

        public String  getName()     { return name; }
        public boolean isPassed()   { return passed; }
        public int     getDuration() { return durationSec; }

        public String toString() {
            String s = passed ? "PASS" : "FAIL";
            return String.format("  [%s] %-28s %2ds  %s", s, name, durationSec, browser);
        }
    }

    // ── Inner Class: TestSuite ────────────────────────────────
    static class TestSuite {
        private String     suiteName;
        private TestCase[] tests;
        private int        size;

        public TestSuite(String name, int capacity) {
            this.suiteName = name;
            this.tests     = new TestCase[capacity];
            this.size      = 0;
        }

        public void addTest(TestCase tc) {
            if (size < tests.length) {
                tests[size++] = tc;
            }
        }

        public void printReport() {
            System.out.println("\n====== SUITE: " + suiteName + " ======");
            int passed = 0, totalTime = 0;
            for (int i = 0; i < size; i++) {
                System.out.println(tests[i]);
                if (tests[i].isPassed()) passed++;
                totalTime += tests[i].getDuration();
            }
            System.out.println("  ──────────────────────────────────────");
            System.out.printf("  Results : %d/%d passed%n", passed, size);
            System.out.printf("  Duration: %d seconds total%n", totalTime);
        }
    }

    // ── MAIN ─────────────────────────────────────────────────
    public static void main(String[] args) {

        TestSuite loginSuite = new TestSuite("Login Module", 5);
        loginSuite.addTest(new TestCase("Valid login",          true,  3, "Chrome"));
        loginSuite.addTest(new TestCase("Wrong password",       false, 2, "Chrome"));
        loginSuite.addTest(new TestCase("Empty fields",          false, 1, "Firefox"));
        loginSuite.addTest(new TestCase("Remember me checkbox",  true,  4, "Edge"));
        loginSuite.printReport();

        TestSuite searchSuite = new TestSuite("Search Module", 3);
        searchSuite.addTest(new TestCase("Search by name",      true,  2, "Chrome"));
        searchSuite.addTest(new TestCase("Search by ID",        true,  1, "Chrome"));
        searchSuite.addTest(new TestCase("Search - no results", false, 3, "Firefox"));
        searchSuite.printReport();
    }
}

Common Mistakes

❌ Constructor with return type

Writing public void User() instead of public User(). Adding a return type makes Java treat it as a regular method, not a constructor. No error, just silently doesn't work as intended.

❌ Forgetting this. in constructor

When parameter and field names match, forgetting this. means you're assigning the parameter to itself. Field stays null/0. Silent bug.

❌ Forgetting new keyword

User u = User("Admin", "pass"); — missing new. Java doesn't know you want to create an object. Compile error.

❌ Accessing private from outside

user.password when password is private. Use the getter: user.getPassword(). Private = only inside the class.

❌ Class name ≠ file name

Class LoginPage must be in file LoginPage.java exactly. Case-sensitive. Mismatch = compile error.

❌ Comparing objects with ==

if (u1 == u2) checks if both variables point to the SAME object in memory. Almost always wrong. Use .equals() or compare individual fields.

❌ Null pointer on uninitialized object

Declaring User u; but not assigning u = new User(...), then calling u.login() — NullPointerException. Always initialize before use.

❌ Calling instance method statically

User.login() when login() is not static. Non-static methods need an object: u.login(). "Non-static method cannot be referenced from static context."
