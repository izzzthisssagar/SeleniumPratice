What is Inheritance?

Inheritance lets a child class automatically get all the fields and methods of a parent class. You write common code once in the parent — all children get it for free. This is the "Don't Repeat Yourself" (DRY) principle in action.

// Inheritance Hierarchy — Parent passes down to Children
03

extends Keyword — Parent & Child Classes

JavaInheritance_Basic.java
// PARENT CLASS (also called: base class, superclass)
public class Animal {
    String name;
    int    age;

    public Animal(String name, int age) {
        this.name = name;
        this.age  = age;
    }

    public void eat() {
        System.out.println(name + " is eating.");
    }

    public void sleep() {
        System.out.println(name + " is sleeping.");
    }
}

// CHILD CLASS (also called: derived class, subclass)
// Dog gets ALL of Animal's fields and methods automatically
public class Dog extends Animal {

    String breed;  // Dog's own additional field

    public Dog(String name, int age, String breed) {
        super(name, age);   // call Animal's constructor first!
        this.breed = breed;
    }

    public void bark() {   // Dog's own method
        System.out.println(name + " says: Woof!");
    }
}

// Using it
Dog d = new Dog("Bruno", 3, "Labrador");
d.eat();    // ✓ inherited from Animal — Bruno is eating.
d.sleep();  // ✓ inherited from Animal — Bruno is sleeping.
d.bark();   // ✓ Dog's own method — Bruno says: Woof!
System.out.println(d.name);   // ✓ inherited field — Bruno
System.out.println(d.breed);  // ✓ own field — Labrador
⚡
Java only supports Single Inheritance for classes

A class can only extend ONE parent class. class Dog extends Animal, Pet is NOT allowed — compile error. To get behavior from multiple sources, use interfaces (Section 10). This is a fundamental Java rule.

04

super Keyword — Accessing Parent Members

super refers to the parent class. Three uses: call parent constructor, call parent method, access parent field. You MUST call super() as the FIRST line in a child constructor if the parent has a non-default constructor.

JavaSuperKeyword.java
public class Vehicle {
    String brand;
    int    speed;

    public Vehicle(String brand, int speed) {
        this.brand = brand;
        this.speed = speed;
        System.out.println("Vehicle created: " + brand);
    }

    public void describe() {
        System.out.println("Brand: " + brand + " | Speed: " + speed);
    }
}

public class Car extends Vehicle {
    int doors;

    public Car(String brand, int speed, int doors) {
        super(brand, speed);  // USE 1: call parent constructor — MUST be first line
        this.doors = doors;
    }

    public void describe() {        // overrides parent's describe()
        super.describe();             // USE 2: call parent method first
        System.out.println("Doors: " + doors);  // then add own info
    }
}

Car c = new Car("Toyota", 180, 4);
// Output: Vehicle created: Toyota   (parent constructor ran first)
c.describe();
// Output: Brand: Toyota | Speed: 180
//         Doors: 4
📌
super() must be the FIRST line in child constructor

If you write anything before super(), you get a compile error: "call to super must be first statement in constructor." If you don't call super() at all and the parent has no default constructor, Java also throws a compile error. Always call it first.

05

Method Overriding — @Override

A child class can replace a parent method with its own version. Same name, same parameters — different body. When you call that method on a child object, the child version runs. The @Override annotation tells Java "I'm intentionally replacing a parent method" — it catches typos.

JavaMethodOverride.java
public class Shape {
    public double area() {
        return 0;
    }
    public void draw() {
        System.out.println("Drawing a shape");
    }
}

public class Circle extends Shape {
    double radius;

    public Circle(double radius) { this.radius = radius; }

    // @Override tells Java: this replaces parent's area()
    @Override
    public double area() {
        return Math.PI * radius * radius;
    }

    @Override
    public void draw() {
        System.out.println("Drawing a circle with radius " + radius);
    }
}

public class Rectangle extends Shape {
    double w, h;
    public Rectangle(double w, double h) { this.w = w; this.h = h; }

    @Override
    public double area() { return w * h; }

    @Override
    public void draw() {
        System.out.println("Drawing rectangle " + w + "x" + h);
    }
}

// Polymorphism: Shape reference holds different object types
Shape[] shapes = { new Circle(5), new Rectangle(4, 6) };
for (Shape s : shapes) {
    s.draw();
    System.out.printf("  Area: %.2f%n", s.area());
}
// Drawing a circle with radius 5.0    Area: 78.54
// Drawing rectangle 4.0x6.0           Area: 24.00
✅
Always write @Override — never skip it

Without @Override, if you spell the method name wrong (e.g. Areaa()), Java silently creates a NEW method instead of overriding. With @Override, Java immediately throws a compile error if the method doesn't match any parent method. It's your safety net.

06

Inheritance Chain — Multi-Level

A child class can itself be extended. This creates a chain: Grandparent → Parent → Child. Each level inherits from all levels above it.

JavaMultiLevel.java
// Level 1 — Grandparent
public class BaseTest {
    public void setupBrowser() {
        System.out.println("Browser started");
    }
    public void teardown() {
        System.out.println("Browser closed");
    }
}

// Level 2 — Parent (extends BaseTest)
public class LoginPageTest extends BaseTest {
    public void navigateToLogin() {
        System.out.println("Navigated to login page");
    }
}

// Level 3 — Child (extends LoginPageTest, inherits from BOTH)
public class LoginValidTest extends LoginPageTest {
    public void testValidLogin() {
        setupBrowser();     // ✓ inherited from BaseTest (2 levels up)
        navigateToLogin(); // ✓ inherited from LoginPageTest (1 level up)
        System.out.println("Running valid login test");
        teardown();         // ✓ inherited from BaseTest (2 levels up)
    }
}

LoginValidTest t = new LoginValidTest();
t.testValidLogin();
// Browser started
// Navigated to login page
// Running valid login test
// Browser closed

What is NOT Inherited

Not InheritedReasonExample
private fieldsPrivate = same class only. Child can't touch them directly.Use getter from parent.
private methodsSame — private scope stays in declaring class.Make it protected if child needs it.
ConstructorsConstructors are not inherited. Must call via super().super(username, password)

JavaPrivateVsProtected.java
public class Parent {
    private   String secret    = "private";   // child CANNOT access
    protected String shared     = "protected"; // child CAN access
    public    String open       = "public";    // everyone CAN access

    protected String getSecret() { return secret; }  // child can call this
}

public class Child extends Parent {
    public void test() {
        // System.out.println(secret); ← ERROR: private, cannot access
        System.out.println(shared);     // ✓ protected — accessible
        System.out.println(open);       // ✓ public — accessible
        System.out.println(getSecret()); // ✓ via protected getter
    }
}

09

Abstract Classes

An abstract class is a class that cannot be instantiated directly — you can only create objects from its subclasses. It can have both regular methods (with code) and abstract methods (no code — subclasses must implement them). Used for BasePage in Selenium.

JavaAbstractClass.java
// abstract class — cannot do: new BasePage()
public abstract class BasePage {

    String url;

    public BasePage(String url) { this.url = url; }

    // Regular method — has implementation, inherited as-is
    public void navigateTo() {
        System.out.println("Navigating to: " + url);
    }

    public void waitForLoad() {
        System.out.println("Waiting for page to load...");
    }

    // Abstract method — no body! Subclasses MUST implement this
    public abstract void verifyPageLoaded();
    public abstract String getPageTitle();
}

// Concrete class — provides implementations for abstract methods
public class LoginPage extends BasePage {

    public LoginPage() {
        super("https://opensource-demo.orangehrmlive.com");
    }

    @Override
    public void verifyPageLoaded() {    // MUST implement abstract method
        System.out.println("Verifying login page elements...");
    }

    @Override
    public String getPageTitle() {      // MUST implement abstract method
        return "OrangeHRM";
    }
}

// new BasePage() ← ERROR: cannot instantiate abstract class
LoginPage page = new LoginPage();  // ✓ concrete class is fine
page.navigateTo();
page.waitForLoad();
page.verifyPageLoaded();
System.out.println(page.getPageTitle());

What is an Interface?

⏰ Hour 2 — Interfaces (60 mins)

An interface is a contract — a list of methods that any implementing class MUST provide. It defines WHAT something can do, not HOW it does it. Before Java 8, interfaces had zero implementation code at all.

// Interface = Contract    Class = Implementation of Contract

Because all three drivers implement WebDriver, your test code can declare WebDriver driver and swap between Chrome, Firefox, or Edge without changing a single line of test code. This is the power of interfaces.

11

implements Keyword

JavaInterfaceImpl.java
// Define the interface (contract)
public interface Testable {
    void setup();         // no body — implementing class must provide it
    void runTest();
    void teardown();
    String getTestName();
}

// Class implements the interface — must provide ALL methods
public class LoginTest implements Testable {

    @Override
    public void setup() {
        System.out.println("Opening Chrome browser...");
    }

    @Override
    public void runTest() {
        System.out.println("Running login test...");
    }

    @Override
    public void teardown() {
        System.out.println("Closing browser...");
    }

    @Override
    public String getTestName() {
        return "Login Module Test";
    }
}

// Use interface as type — can hold any implementing class
Testable test = new LoginTest();
test.setup();
test.runTest();
test.teardown();
System.out.println(test.getTestName());
🚨
Must implement ALL methods from interface

If your class says implements Testable but doesn't provide all 4 methods, you get a compile error: "class must implement abstract method." No exceptions — you implement ALL or none (unless it's an abstract class).

Multiple Interfaces

A class can implement multiple interfaces — this is how Java gives you "multiple inheritance" safely. Each interface adds a new capability.

JavaMultipleInterfaces.java
public interface Loggable {
    void logInfo(String msg);
    void logError(String msg);
}

public interface Screenshottable {
    void takeScreenshot(String filename);
}

public interface Reportable {
    void generateReport();
}

// One class implements ALL THREE — gets all capabilities
public class TestRunner implements Loggable, Screenshottable, Reportable {

    @Override
    public void logInfo(String msg)  { System.out.println("[INFO] " + msg); }

    @Override
    public void logError(String msg) { System.out.println("[ERROR] " + msg); }

    @Override
    public void takeScreenshot(String f) {
        System.out.println("Screenshot saved: " + f);
    }

    @Override
    public void generateReport() {
        System.out.println("HTML report generated.");
    }
}

TestRunner runner = new TestRunner();
runner.logInfo("Test started");
runner.takeScreenshot("login_fail.png");
runner.logError("Element not found");
runner.generateReport();

Default Methods in Interfaces (Java 8+)

Since Java 8, interfaces can have default methods — methods with a body that implementing classes can use or override. This lets you add new methods to an interface without breaking all existing implementations.

JavaDefaultMethod.java
public interface Clickable {

    // Abstract — implementing class MUST provide this
    void click();

    // Default — implementing class CAN override, but doesn't have to
    default void clickAndWait(int seconds) {
        click();   // calls the abstract method
        System.out.println("Waiting " + seconds + " seconds after click");
    }

    // Static method in interface — called via InterfaceName.method()
    static void printInfo() {
        System.out.println("Clickable interface — use for all clickable elements");
    }
}

public class Button implements Clickable {
    String label;
    public Button(String label) { this.label = label; }

    @Override
    public void click() { System.out.println("Clicked: " + label); }
    // clickAndWait is inherited from interface default — no need to override
}

Button btn = new Button("Submit");
btn.click();            // Clicked: Submit
btn.clickAndWait(2);   // Clicked: Submit  |  Waiting 2 seconds after click
Clickable.printInfo(); // static method on interface

Selenium BaseTest — Real Framework Pattern

This is exactly how your test framework will be structured on Day 37+. Study this closely — it combines inheritance, constructors, and the lifecycle pattern used by TestNG.

JavaBaseTest.java — Your actual framework (Day 37+)
// Parent class — written ONCE, used by ALL test classes
public class BaseTest {

    // WebDriver driver;  ← real Selenium (Day 13+)
    String browser;

    public BaseTest(String browser) {
        this.browser = browser;
    }

    // @BeforeMethod in TestNG — runs before EACH test
    public void setUp() {
        System.out.println("[SETUP] Starting " + browser + " browser");
        // driver = new ChromeDriver(); ← Day 11
    }

    // @AfterMethod in TestNG — runs after EACH test
    public void tearDown() {
        System.out.println("[TEARDOWN] Closing browser");
        // driver.quit(); ← Day 11
    }

    public void takeScreenshot(String name) {
        System.out.println("[SCREENSHOT] Saved: " + name + ".png");
    }
}

// Child class — only has login-specific tests
public class LoginTest extends BaseTest {

    public LoginTest() {
        super("Chrome");  // pass browser to BaseTest
    }

    public void testValidLogin() {
        setUp();                   // inherited
        System.out.println("  → Entering credentials");
        System.out.println("  → Clicking login");
        System.out.println("  → Verifying dashboard");
        System.out.println("  ✓ LOGIN TEST PASSED");
        tearDown();                // inherited
    }

    public void testInvalidLogin() {
        setUp();
        System.out.println("  → Entering wrong password");
        System.out.println("  → Verifying error message");
        takeScreenshot("invalid_login_fail");  // inherited
        System.out.println("  ✓ INVALID LOGIN TEST PASSED");
        tearDown();
    }
}

// Run it
LoginTest t = new LoginTest();
t.testValidLogin();
System.out.println();
t.testInvalidLogin();

WebDriver Interface in Selenium

This is the most important real-world interface you'll use. Understanding it now means Day 11 (First Selenium Script) will feel natural, not confusing.

JavaWebDriverInterface.java — Selenium Day 11+ preview
// WebDriver is an INTERFACE defined by Selenium
// ChromeDriver, FirefoxDriver, EdgeDriver all implement it

// Day 11 — you'll write this:
// WebDriver driver = new ChromeDriver();   ← interface type, ChromeDriver object
// WebDriver driver = new FirefoxDriver();  ← SAME variable, different browser
// WebDriver driver = new EdgeDriver();     ← swap browsers by changing ONE line

// Because WebDriver is the type, your test code works with ANY browser:
// driver.get("https://site.com");    ← works for chrome, firefox, edge
// driver.findElement(By.id("btn")); ← works for all
// driver.getTitle();                 ← works for all
// driver.quit();                     ← works for all

// This is EXACTLY the same pattern as:
interface WebDriver {          // contract
    void get(String url);
    String getTitle();
    void quit();
}

class ChromeDriver implements WebDriver {   // chrome implementation
    public void get(String url)  { System.out.println("Chrome → " + url); }
    public String getTitle()    { return "Chrome Title"; }
    public void quit()          { System.out.println("Chrome closed"); }
}

class FirefoxDriver implements WebDriver {  // firefox implementation
    public void get(String url)  { System.out.println("Firefox → " + url); }
    public String getTitle()    { return "Firefox Title"; }
    public void quit()          { System.out.println("Firefox closed"); }
}

// Test works with BOTH — just change the right side
WebDriver driver = new ChromeDriver();
driver.get("https://orangehrm.com");  // Chrome → https://orangehrm.com
System.out.println(driver.getTitle());
driver.quit();

driver = new FirefoxDriver();        // swap — test code unchanged!
driver.get("https://orangehrm.com");  // Firefox → https://orangehrm.com
driver.quit();
🌟
You just understood how Selenium's core architecture works

WebDriver driver = new ChromeDriver() — that single line you'll write 100 times in Phase 2 — is just interface polymorphism. The interface type on the left, the concrete implementation on the right. Today is the day that line stops being magic and starts making sense.

Practice Task + Expected Output

JavaDay5Practice.java
public class Day5Practice {

    // ── Interface ────────────────────────────────────────────
    interface TestLifecycle {
        void beforeTest();
        void afterTest();
        String getTestName();

        default void runWithLifecycle() {
            beforeTest();
            System.out.println("  Running: " + getTestName());
            afterTest();
        }
    }

    // ── Abstract base ────────────────────────────────────────
    static abstract class BaseTest implements TestLifecycle {
        protected String browser;
        protected int    passCount = 0;
        protected int    failCount = 0;

        public BaseTest(String browser) {
            this.browser = browser;
        }

        @Override
        public void beforeTest() {
            System.out.println("  [SETUP] " + browser + " started");
        }

        @Override
        public void afterTest() {
            System.out.println("  [DONE] Pass:" + passCount + " Fail:" + failCount);
        }

        // Abstract — each subclass defines its own steps
        public abstract void executeTests();
    }

    // ── Concrete child 1 ─────────────────────────────────────
    static class LoginTest extends BaseTest {
        public LoginTest() { super("Chrome"); }

        @Override
        public String getTestName() { return "Login Module"; }

        @Override
        public void executeTests() {
            System.out.println("    ✓ Valid login");       passCount++;
            System.out.println("    ✗ Wrong password");     failCount++;
            System.out.println("    ✓ Remember me");        passCount++;
        }
    }

    // ── Concrete child 2 ─────────────────────────────────────
    static class SearchTest extends BaseTest {
        public SearchTest() { super("Firefox"); }

        @Override
        public String getTestName() { return "Search Module"; }

        @Override
        public void executeTests() {
            System.out.println("    ✓ Search by name");    passCount++;
            System.out.println("    ✓ Search by ID");      passCount++;
            System.out.println("    ✗ No results found");  failCount++;
        }
    }

    // ── WebDriver interface demo ──────────────────────────────
    interface WebDriver {
        void get(String url);
        String getBrowser();
        void quit();
    }

    static class ChromeDriver implements WebDriver {
        public void get(String url) { System.out.println("  Chrome → " + url); }
        public String getBrowser()  { return "Chrome"; }
        public void quit()         { System.out.println("  Chrome closed"); }
    }

    static class FirefoxDriver implements WebDriver {
        public void get(String url) { System.out.println("  Firefox → " + url); }
        public String getBrowser()  { return "Firefox"; }
        public void quit()         { System.out.println("  Firefox closed"); }
    }

    // ── MAIN ─────────────────────────────────────────────────
    public static void main(String[] args) {

        System.out.println("====== TEST SUITE RUN ======");

        BaseTest[] tests = { new LoginTest(), new SearchTest() };
        for (BaseTest t : tests) {
            t.runWithLifecycle();   // default method from interface
            t.executeTests();      // abstract method — each class does its own
            t.afterTest();          // overridden from BaseTest
            System.out.println();
        }

        System.out.println("====== WEBDRIVER DEMO ======");
        WebDriver[] drivers = { new ChromeDriver(), new FirefoxDriver() };
        for (WebDriver d : drivers) {
            System.out.println("Using: " + d.getBrowser());
            d.get("https://orangehrm.com");
            d.quit();
        }
    }
}

Common Mistakes

❌ extends multiple classes

class Dog extends Animal, Pet — NOT allowed. Java only supports single class inheritance. Use interfaces for multiple behaviors.

❌ Forgetting super() in child

If parent has a constructor with parameters and child doesn't call super(), compile error. Always call super(args) as first line.

❌ Overriding private method

Private methods can't be overridden — child creates a NEW method with same name instead. Use protected if child needs to override it.

❌ Not implementing all interface methods

If you implement an interface and miss any method, you get compile error unless the class is declared abstract.

❌ Calling super() mid-method

super() must be the VERY FIRST line in a constructor. Putting it after any other statement = compile error.

❌ Instantiating abstract class

new BasePage() when BasePage is abstract — compile error. You can only instantiate concrete subclasses.

❌ Typo in @Override method

Without @Override, a typo creates a new method silently. Always use @Override so Java catches mismatches immediately.

❌ Interface fields aren't mutable

All fields in an interface are implicitly public static final. You can't have regular instance fields in an interface — only constants.
