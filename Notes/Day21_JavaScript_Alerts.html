What Are JavaScript Alerts?

⏰ Hour 1 — Alert Fundamentals (60 mins)

JavaScript alerts are native browser dialogs that block all interaction with the page until handled. They appear when JavaScript code calls alert(), confirm(), or prompt(). Until you handle them, Selenium cannot interact with any page elements — every command throws UnhandledAlertException.

⚡
Alerts block everything — handle immediately

When an alert appears, the browser is frozen. Any driver.findElement(), driver.get(), or any other command will throw UnhandledAlertException. Always switch to and handle the alert before doing anything else.

Simple Alert — accept()

JavaSimpleAlert.java
import org.openqa.selenium.Alert;

// Trigger alert via JavaScript (for practice)
((JavascriptExecutor) driver).executeScript("alert('Welcome to OrangeHRM!')");

// Step 1: Switch to the alert
Alert alert = driver.switchTo().alert();

// Step 2: Read the message
String message = alert.getText();
System.out.println("Alert message: " + message);
// Alert message: Welcome to OrangeHRM!

// Step 3: Accept (click OK)
alert.accept();
System.out.println("Alert accepted");

// Can now interact with page again
System.out.println("Page title: " + driver.getTitle());

prompt2.accept();

// Cancel the prompt (returns null to JS)
((JavascriptExecutor) driver).executeScript("prompt('Cancel me')");
driver.switchTo().alert().dismiss(); // click Cancel

Waiting for Alerts with WebDriverWait

JavaWaitForAlert.java
import org.openqa.selenium.support.ui.ExpectedConditions;
import org.openqa.selenium.support.ui.WebDriverWait;
import java.time.Duration;

WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(5));

// Trigger alert (may take time on slow apps)
driver.findElement(By.id("deleteBtn")).click();

// Wait until alert is present, then switch to it
Alert alert = wait.until(ExpectedConditions.alertIsPresent());

// Now handle it safely
System.out.println("Alert: " + alert.getText());
alert.accept();

// Full pattern — trigger → wait → read → handle
public static String handleAlert(WebDriver driver, boolean accept) {
    WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(5));
    Alert alert = wait.until(ExpectedConditions.alertIsPresent());
    String text = alert.getText();
    if (accept) alert.accept();
    else        alert.dismiss();
    return text;
}

Checking if Alert is Present

JavaAlertCheck.java
// Safe check — returns true if alert is present
public static boolean isAlertPresent(WebDriver driver) {
    try {
        driver.switchTo().alert();
        return true;
    } catch (NoAlertPresentException e) {
        return false;
    }
}

// Usage
if (isAlertPresent(driver)) {
    Alert a = driver.switchTo().alert();
    System.out.println("Alert found: " + a.getText());
    a.accept();
} else {
    System.out.println("No alert present");
}

// Using WebDriverWait with 0 timeout — instant check
public static boolean isAlertPresentWait(WebDriver driver) {
    try {
        new WebDriverWait(driver, Duration.ofSeconds(1))
            .until(ExpectedConditions.alertIsPresent());
        return true;
    } catch (TimeoutException e) {
        return false;
    }
}

Unexpected Alerts — Handling Gracefully

⏰ Hour 2 — Advanced Patterns (60 mins)

Sometimes alerts appear at unexpected times — session timeouts, server messages, browser warnings. Wrap your test steps to handle these gracefully.

JavaUnexpectedAlert.java
// Scenario: Alert appears during normal test flow
// Without handling: UnhandledAlertException crashes test

// Method: wrap any action that might trigger an alert
public static boolean safeClick(WebDriver driver, By locator) {
    try {
        driver.findElement(locator).click();
        return true;
    } catch (UnhandledAlertException e) {
        // Alert appeared — dismiss it and report
        System.out.println("Unexpected alert: " + e.getMessage());
        try {
            driver.switchTo().alert().accept();
        } catch (NoAlertPresentException ignored) {}
        return false;
    }
}

// Session timeout alert handler
public static void dismissIfAlertPresent(WebDriver driver) {
    try {
        Alert alert = new WebDriverWait(driver, Duration.ofSeconds(1))
            .until(ExpectedConditions.alertIsPresent());
        System.out.println("Auto-dismissed alert: " + alert.getText());
        alert.dismiss();
    } catch (TimeoutException ignored) {
        // No alert — that's fine
    }
}

// Call before sensitive operations
dismissIfAlertPresent(driver);
driver.findElement(By.id("nextStep")).click();

Triggering Alerts via JavaScript

JavaTriggerAlerts.java
JavascriptExecutor js = (JavascriptExecutor) driver;
WebDriverWait wait    = new WebDriverWait(driver, Duration.ofSeconds(5));

// 1. Simple alert
js.executeScript("alert('Hello! This is a simple alert.')");
Alert a1 = wait.until(ExpectedConditions.alertIsPresent());
System.out.println("Alert: " + a1.getText());
a1.accept();

// 2. Confirm — capture result
js.executeScript("window._result = confirm('Confirm this action?')");
Alert a2 = wait.until(ExpectedConditions.alertIsPresent());
System.out.println("Confirm: " + a2.getText());
a2.accept(); // user clicks OK
// window._result is now true (accessible via JS)

// 3. Prompt
js.executeScript("window._input = prompt('What is your name?', '')");
Alert a3 = wait.until(ExpectedConditions.alertIsPresent());
a3.sendKeys("Sagar");
a3.accept();
// window._input is now "Sagar"
String input = (String) js.executeScript("return window._input");
System.out.println("User entered: " + input); // Sagar

AlertHelper Utility

JavaAlertHelper.java — utils/AlertHelper.java
package com.qaautomation.utils;

import org.openqa.selenium.*;
import org.openqa.selenium.support.ui.*;
import java.time.Duration;

public class AlertHelper {

    private static WebDriverWait getWait(WebDriver d) {
        return new WebDriverWait(d, Duration.ofSeconds(5));
    }

    // Check if alert is present
    public static boolean isPresent(WebDriver d) {
        try {
            getWait(d).until(ExpectedConditions.alertIsPresent());
            return true;
        } catch (TimeoutException e) {
            return false;
        }
    }

    // Get alert text
    public static String getText(WebDriver d) {
        return getWait(d).until(ExpectedConditions.alertIsPresent()).getText();
    }

    // Accept alert (click OK)
    public static String accept(WebDriver d) {
        Alert a = getWait(d).until(ExpectedConditions.alertIsPresent());
        String text = a.getText();
        a.accept();
        return text;
    }

    // Dismiss alert (click Cancel)
    public static String dismiss(WebDriver d) {
        Alert a = getWait(d).until(ExpectedConditions.alertIsPresent());
        String text = a.getText();
        a.dismiss();
        return text;
    }

    // Type in prompt then accept
    public static void typeAndAccept(WebDriver d, String text) {
        Alert a = getWait(d).until(ExpectedConditions.alertIsPresent());
        a.sendKeys(text);
        a.accept();
    }

    // Dismiss if present (won't fail if no alert)
    public static void dismissIfPresent(WebDriver d) {
        try {
            getWait(d).until(ExpectedConditions.alertIsPresent()).dismiss();
        } catch (TimeoutException ignored) {}
    }
}

Common Mistakes

❌ Forgetting switchTo().alert()

All alert operations need driver.switchTo().alert() first — getText(), accept(), dismiss() all require it. Calling them on driver directly throws errors.

❌ Not waiting for alert

Calling driver.switchTo().alert() before alert appears throws NoAlertPresentException. Always use WebDriverWait + alertIsPresent() for alerts triggered by async operations.

❌ Interacting with page during alert

Any driver.findElement() or navigation while alert is open throws UnhandledAlertException. Handle the alert first — then proceed with page interactions.

❌ sendKeys on non-prompt alert

alert.sendKeys() only works on prompt() dialogs. Calling it on a simple alert() or confirm() dialog may throw or silently fail. Check dialog type first.

❌ dismiss() on simple alert

Simple alert() has only an OK button — calling dismiss() still closes it, but it's confusing code. Use accept() for simple alerts to make intent clear.

❌ Not switching back after handling

After handling an alert, you're automatically back in the main page context — no need to switchTo().defaultContent(). But if you had switched to a frame before the alert, you need to re-enter it.
