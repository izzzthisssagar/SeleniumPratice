What is Java? — The Big Picture

Java is a high-level, object-oriented, platform-independent programming language created by James Gosling at Sun Microsystems in 1995. Today it is owned by Oracle.

In the world of test automation, Java is the #1 language used with Selenium WebDriver in enterprise environments — especially in Nepal, India, and globally. Most QA job descriptions that mention Selenium also expect Java.

Why Java for Automation?

ReasonWhat it means for you
Most used with SeleniumSelenium was built in Java. Most documentation and tutorials are Java-first.
Strongly typedCatches errors at compile time, not at runtime. Safer test code.
OOP supportPage Object Model (POM) pattern relies completely on OOP concepts.
Large ecosystemMaven, TestNG, JUnit, Allure, ExtentReports — all Java-native.
Job marketNepal's top IT companies (Leapfrog, Cotiviti) use Java-Selenium extensively.
💡
Java vs Other Languages for Selenium

Python is simpler to learn but Java dominates in enterprise QA. Since your goal is jobs at companies like Leapfrog and Cotiviti, Java is the correct choice. Stick with it.

08

String — The Non-Primitive You Must Know

String is technically a class (not a primitive), but it behaves like one in everyday use. It represents a sequence of characters. In Selenium, String is the most-used data type — URLs, button text, locators, assertions — all use String.

⚡
Critical: String uses double quotes. char uses single quotes.

String name = "Sagar"; ← double quotes ✅
char initial = 'S'; ← single quotes ✅
String name = 'Sagar'; ← WRONG, compile error ❌

Essential String Methods for Selenium

JavaStringMethods.java
String text = "  OrangeHRM Login  ";

// length — how many characters
System.out.println(text.length());          // 19

// trim — remove spaces from start and end
System.out.println(text.trim());            // "OrangeHRM Login"

// toLowerCase / toUpperCase
System.out.println(text.toLowerCase());     // "  orangehrm login  "
System.out.println(text.toUpperCase());     // "  ORANGEHRM LOGIN  "

// contains — check if text has a substring
System.out.println(text.contains("Login")); // true

// equals — compare two strings (NEVER use ==)
String a = "Admin";
String b = "Admin";
System.out.println(a.equals(b));           // true ✅
System.out.println(a == b);                 // may be false! ❌

// replace — replace part of string
String url = "https://test.site.com";
System.out.println(url.replace("test", "prod")); // https://prod.site.com

// split — break string into array
String csv = "login,logout,register";
String[] tests = csv.split(",");            // ["login","logout","register"]

// isEmpty — check if string is empty
String empty = "";
System.out.println(empty.isEmpty());        // true
🚨
NEVER use == to compare Strings

== checks if they are the same object in memory, not if they have the same value. .equals() checks the actual content. In Selenium assertions, wrong String comparison is a top cause of false-passing tests.

Type Casting — Implicit & Explicit

Type casting means converting one data type to another. This happens often in Selenium when reading text from web pages (always String) and comparing it to numbers.

// Widening vs Narrowing Casting
JavaTypeCasting.java
// WIDENING — automatic (smaller → larger type)
int myInt = 10;
double myDouble = myInt;   // auto-converts: 10 → 10.0
System.out.println(myDouble); // 10.0

// NARROWING — manual (larger → smaller, use with care)
double price = 9.99;
int rounded = (int) price;   // 9 — decimal CHOPPED off (not rounded!)
System.out.println(rounded);  // 9

// STRING ↔ INT conversion (very common in Selenium)
// String to int
String numStr = "42";
int num = Integer.parseInt(numStr);   // 42

// int to String
int count = 5;
String countStr = String.valueOf(count); // "5"
String countStr2 = "" + count;         // "5" (shorthand)

// Selenium example: getText() returns String,
// but you need to compare the number:
String pageText = "Total Items: 25";
String countText = pageText.split(":")[1].trim(); // "25"
int totalItems = Integer.parseInt(countText);     // 25

Java has strict naming conventions. Interviewers will notice instantly if your code breaks these. Follow them from Day 1 so they become muscle memory.

WhatConventionExample❌ Wrong
VariablescamelCase — starts lowercasefirstName, isLoggedInFirstName, first_name
MethodscamelCase — starts lowercase, verbgetUser(), clickLogin()GetUser(), get_user()
ClassesPascalCase — every word capitalizedLoginPage, UserTestloginPage, login_page
ConstantsALL_CAPS with underscoresMAX_TIMEOUT, BASE_URLmaxTimeout, baseUrl
Packagesall lowercase, dot-separatedcom.company.testsCom.Company.Tests

Rules for Variable Names

JavaNamingRules.java
// ✅ VALID names
int age = 22;
String firstName = "Sagar";
boolean isTestPassed = true;
int _count = 5;       // underscore allowed at start
int $value = 10;      // $ allowed (but avoid in practice)

// ❌ INVALID names (compile error)
// int 2count = 5;      → cannot start with number
// int my-value = 5;    → hyphen not allowed
// int class = 5;       → 'class' is a reserved keyword
// int int = 5;         → 'int' is a reserved keyword

Constants — The final Keyword

A constant is a variable whose value cannot be changed after it's assigned. Use the final keyword. In Selenium frameworks, constants are used for base URLs, timeouts, and credentials.

JavaConstants.java
// Declaring a constant
final int MAX_TIMEOUT = 30;
final String BASE_URL = "https://opensource-demo.orangehrmlive.com";
final String ADMIN_USER = "Admin";

// Trying to change a constant → compile error
// MAX_TIMEOUT = 60;  → ERROR: cannot assign a value to final variable

// In Selenium, you'll see this often:
public class Config {
    public static final String BASE_URL = "https://site.com";
    public static final int IMPLICIT_WAIT = 10;
    public static final String BROWSER = "chrome";
}

Comments in Java

Comments are notes in your code that Java ignores during compilation. They explain why something is done, not what is done (the code itself shows what).

JavaCommentsDemo.java
// 1. Single-line comment — use for quick notes
int timeout = 30; // seconds — industry standard for explicit wait

/*
 * 2. Multi-line comment — use for longer explanations
 * This method opens a browser and navigates to the login page.
 * Call this at the start of every test that needs authentication.
 */
public static void openLoginPage() {
    // implementation here
}

/**
 * 3. JavaDoc comment — use above classes and methods
 * Generates automatic documentation.
 *
 * @param username  the admin username
 * @param password  the admin password
 * @return          true if login succeeds, false otherwise
 */
public boolean login(String username, String password) {
    return true;
}
💡
When to comment and when NOT to

Comment WHY: // Using bcryptjs instead of bcrypt for cross-platform support
Don't comment WHAT: // adding 1 to i above i++ — the code is self-explanatory.

Print Statements & String Formatting

JavaPrintStatements.java
String name = "Sagar";
int age = 22;
double score = 98.5;

// println — prints then moves to new line
System.out.println("Hello World");

// print — prints WITHOUT moving to new line
System.out.print("Hello ");
System.out.print("Sagar");   // Output: Hello Sagar (same line)

// String concatenation with + operator
System.out.println("Name: " + name + ", Age: " + age);

// printf — formatted output (like C-style)
System.out.printf("Name: %s, Age: %d, Score: %.1f%n", name, age, score);
// Output: Name: Sagar, Age: 22, Score: 98.5

// String.format — build formatted string (preferred in Selenium)
String message = String.format("Test FAILED for user: %s", name);
System.out.println(message);

// Format specifiers:
// %s = String     %d = int/long    %f = float/double
// %b = boolean    %n = newline     %.2f = 2 decimal places

Common Mistakes — Day 1

❌ Lowercase 'string'

string name = "x"; → Error. Java's String class is capital S. Always String.

❌ Missing semicolons

int x = 5 → Compile error. Every statement in Java ends with ;. No exceptions.

❌ == to compare Strings

if (a == b) on Strings compares object references, not content. Always use .equals().

❌ Class name ≠ filename

If your class is Day1Practice but file is day1.java — compile error. Must match exactly.

❌ Integer division bug

int result = 48 / 50; gives 0, not 0.96. Both are int so decimal is chopped. Cast first: (double) 48 / 50.

❌ Unmatched braces

Every { needs a closing }. IntelliJ shows red underline. Count your braces carefully in early days.

❌ Variable before declaration

Using a variable before declaring it: System.out.println(x); int x = 5; → Error. Declare first, use after.

❌ Single quotes for String

String name = 'Sagar'; → Error. Single quotes are for char only. Strings need double quotes.
